## 内存事务基础

新增 `compareAndWriteMemory`：在核心锁内先比较全部预期字节，再统一写入；任一比较失败不写入。仅接收 canonical EWRAM/IWRAM，最多 64 段、合计 16 KiB；拒绝重叠、镜像、越界、空段、长度不一致。相同的新旧字节可作为只读条件。

此桥仅提供原子比较与写入。构建能力、场景、合法操作、实验分支、恢复点和结果重读由上层命令服务负责，不能据此宣称火纹编辑或正常背包操作已完成。

2026-11-01 验证：

- Android debug、instrumentation APK 与 JVM 测试构建通过。
- NDK arm64/API 26 的 `-Wall -Wextra -Werror -fsyntax-only` 通过。
- 独立 API 35 x86_64 测试模拟器执行 `NativeCoreSmokeTest` 5 项和 `MemoryTransactionTest` 5 项，全部通过。
- 事务测试覆盖双 RAM 区域提交、无帧推进、失配无部分修改、非法输入、恰好 64 段/16 KiB、保存重开、恢复原点，以及主分支所有文件摘要不变。
- 使用仓库生成的原创诊断 ROM；上述事务测试没有在 Thor 的用户进度上执行。

## 界面与开发模拟器观测

已在独立测试模拟器检查单屏横屏、虚拟副屏显示及场景信息；光标由 `(4,5)` 移至 `(4,4)` 时，详情由 HP16/16 更新为 HP13/30。固定对象操作与场景失效另有运行时测试。实际界面执行创建实验分支、确认 HP16→15、恢复编辑前状态，表单重读回到16。布局可滚动，未知名称有解释，错误跨页显示，恢复入口独立于新编辑能力。

一次持续运行观测在捕获 1992 次时，最近窗口 P95 为捕获 **2.5 ms**、解码 **2.6 ms**、捕获至 owner 发布 **7.5 ms**、帧工作 **3.1 ms**；累计 20 帧工作超过 16.742706 ms。统计窗口分别保留最近 120 个有效样本；这是 Windows 开发机上的软件图形模拟器，同时存在构建／UI 自动化负载，不是 Thor 性能结论。发布延迟不包含四帧采样等待或 Compose 实际显示延迟，不能冒称实体按键到画面的响应测量。

本轮未向 Thor 安装 M1 构建或写入其用户进度；既有 M0 实机反馈不能替代 M1 的性能与交互验收。
