# M0 本地目标文件登记

核验日期：2026-11-01（Asia/Shanghai）。依据 [项目方案](PROJECT_PLAN.md) 与 [M0 输入登记任务](IMPLEMENTATION_TASKS.md#m0-工程地基与输入登记)。

本次只读检查用户提供的 `roms/` 中 **7 个 GBA 文件**，计算完整文件指纹并校验文件大小、GBA 固定位和文件头 checksum。其中 6 个通过并登记到本地 `.local/targets.json`；烈火之剑 Plus 的文件头 checksum 不符，登记工具按既定规则拒绝该文件。登记前后逐个复算 SHA-256，所有源文件均未改变。

`.local/targets.json` 仅保存本地原路径和元数据，不复制 ROM，且不提交到仓库。本文件仅公开文件名、大小、指纹及核验结论，不包含 ROM 内容或个人绝对路径。

## 声明与验证边界

- `role` 是根据用户提供的文件名称及本次用途登记的作品类别声明；`compatibility_verified` 均为 `false`。接受 `fe6` 角色仅扩展登记工具，**不改变 FE6 位于 M6 的适配顺序**。
- “文件头通过”只表示大小在 192 字节至 32 MiB 之间、`0xB2` 为 `0x96`、`0xA0..0xBC` 的 checksum 与 `0xBD` 一致，不代表官方原版真实性或火纹语义兼容性。本次未与官方发行指纹目录比对。
- 表中的日版、汉化、语音版、Plus 和版本号来自文件名声明；header 是实际读取值。它们都不能替代文本、RAM 布局、游戏规则、操作和事件的独立验证。
- 此清单不宣称已经运行或完成任何一份 ROM 的适配。运行核心、恢复和实机测试的结果应另附验证记录。

## 对实施顺序的影响

1. **FE8 样本已到位，但不是 FE8U 基线。** R03 与 R04 的 header 均为 `BE8J`，且大小、完整指纹不同。R04 的中文语音版不得直接复用 FE8U 地址或因相同 header 而沿用 R03 布局。M1 仍须选定具体构建并独立核验。
2. **FE7 有日版声明与汉化声明两个样本。** R02 与 R06 具有相同 `AE7J` header、相同大小、不同完整指纹；文本、布局与操作差异须分别验证。
3. **目录已出现明确以《天地之剑》命名的文件。** R05 在核验期间新增，按其名称登记为目标候选。文件名中的 `202410`、`1.22`、汉化重置及 `AE7J` header 不能单独证明补丁来源、最终布局和技能机制，M2／M3 继续核验该具体指纹。R07 的烈火 Plus 是另一份文件，未被认作天地之剑。
4. **FE6 保留为后续输入。** R01 已登记，不提前宣称适配完成。
5. **Plus 文件继续保持拒绝状态。** 只有核实文件来源或另行明确适配策略后再处理；本次不会静默修改用户文件来满足校验。
