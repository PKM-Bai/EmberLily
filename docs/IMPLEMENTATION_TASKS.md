# EmberLily 分阶段实施任务

依据：[已确认项目方案](PROJECT_PLAN.md)。确认日期：2026-11-01（Asia/Shanghai）。

M0 已于 2026-11-01 通过阶段验收。M1 进展见 [M1 验证记录](M1_VALIDATION.md)；按用户调整完成上屏扩景后，已提前进入 [M2 基础适配](M2_VALIDATION.md)。M1 和 M2 的正常背包、完整场景与 Thor 新版验收仍保留，M3—M6 尚未开始。

## 执行约定

- 顺序为 M0 → M1 → M2 → M3 → M4 → M5 → M6。M1—M3 验证基础能力，M5 才是 v0.1 发布门槛。
- 2026-11-01 用户调整当前执行顺序：完成上屏去按键、沉浸式显示和真实地图扩景后，提前推进 M2。M1 尚未完成的正常背包、完整场景与性能验收继续保留，不以提前接入 FE7 视为 M1 关闭。
- 验收编号 A01—A12 对应 [项目方案的验收标准](PROJECT_PLAN.md#9-验收标准)。
- 每个任务完成后记录改动、验证构建、实际通过／跳过／未覆盖项及剩余问题。
- 阶段、功能或修复完成后的提交推送遵循 [协作与交付约定](../AGENTS.md)。
- 不因同一基础引擎或相同 header 自动继承改版能力。目标文件、样本及验证记录有明确对应关系。
- M4 可在稳定接口上分工并行，核心写入路径和同一会话的验证需要串行协调。
