# FE7 背包场景补充样本

采样日期：2026-11-01。关联 [M2 验证记录](M2_VALIDATION.md) 与 [FE7J 技术依据](FE7J_EVIDENCE.md)。本记录提供原作流程的研究材料，不代表副屏已经支持 FE7 交换或道具使用。

## 最早准备章节

在 R02、R06 两份已登记文件中，实际读取 `GetChapterInfo` 的 ROM 字面量 `0x08031A6C` 均指向 `0x08D62110`。章节记录大小为 `0x94`，`has_prep` 字段位于 `+0x0D`。两构建章节索引 `0..6` 的该字段均为0，`7..11` 均为1；第一个声明开启准备画面的章节是索引7，即琳篇第7章。

字段和读取方式与锁定的 FireEmblem7J 源码 `include/gbafe/chapterdata.h`、`include/constants/chapters.h` 及 `asm/code1.s` 的 `GetChapterInfo` 一致。`src/eventscr.c` 中 `EvtCmd_ClearSkipFadeToPrep` 也使用该字段区分准备阶段的淡入行为。

这说明从现有序章进度取得正常准备交换样本需要继续推进多个章节；它不证明仅改章节编号即可创建合法准备上下文。本轮没有修改章节、事件标记或单位属性来跳过流程，也未取得 FE7 准备交换样本。R02 的本轮证据仅为静态核对，以下运行样本仅属于 R06。

## R06 原生物品菜单与伤药使用

目标 SHA-256：`828b8bb1bff54a66b89cb1e43901d88bb783a4da6e543ac31aa6edc17e162d25`。

从既有 `r06-agent-idle.state`（SHA-256 `34ea61fcf0a4ac24594d65d6dd8929dd44cb05f24fd35e601d127452b9a0faeb`）在独立 API35 x86_64 模拟器执行原生方向键、A/B/START 输入，完成序章首战及第三回合的移动／物品教学。没有通过副屏命令或 RAM 写入完成这些动作。初始部署遇到测试目录缺少读取权限，修复仅测试设备目录权限后采样通过；该部署失败不计作游戏兼容失败。

所有输出为新的独立状态，存放在忽略目录 `.local/inventory-samples/probes/`。每份同名前缀包含 `.state`、`.ewram.bin`、`.iwram.bin`、`.png` 和 `.json`；JSON 记录输入序列、父状态指纹和输出指纹。ROM 及初始状态在采样后复核指纹不变。样本不随仓库分发，未访问或修改 Thor 存档；采样使用的 `emulator-5556` 已关闭。
