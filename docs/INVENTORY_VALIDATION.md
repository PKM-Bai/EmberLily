# 副屏背包与准备交换验证

## 交付范围

`0.0.6-m2-preview`（versionCode 6）增加独立“背包”页签。R04／R02／R06 在有效场景可查看已解析角色物品和仓库，按阵营、真实角色槽、类别、空槽筛选，并用不依赖 IME 的触摸十六进制键盘按编号精确查找；物品详情可固定另一个实例左右逐行比较。物品和仓库读取依据见 [读取证据](INVENTORY_READING_EVIDENCE.md)。R03 只有静态物品能力，界面不因能够加载表就开放未验收的实时背包。

单项物品保留名称／类别／耐久、真实拥有者与槽位；基础威力／命中／必杀／重量／射程不解释为角色实际战斗预测。普通道具不展示不适用的武器数值，不可损坏和特殊射程独立处理。中文文本仍显示编号，不声称已完成中文名称搜索。仓库只读不意味着当前游戏允许取放。

## 已验证的准备交换范围

目标限定为 R04 `4853c904c1c180f837678f3d0032dbbb86049bc710fb1993fb51bad8c49b1076`。副屏只操作原游戏当前准备交换子画面的两名角色；上屏须先进入该子画面。此能力包括交换两件完整物品，以及把物品转交到对方第一个空位。它不是任意全军远程转移、仓库存取、战场交换或研究写入。

命令调用原游戏方向键与 A 键，未写入物品 RAM、未调用 ROM 函数跳板。每一步在模拟线程中推进原生帧、重新捕获 RAM 并核验，交换由游戏自己执行压紧与界面刷新。领域请求绑定 ROM／会话／分支／epoch／revision、活跃 Proc、两名实际单位及双方全部十个 u16 原值；UI 筛选或排序位置不充当物品槽地址。

## 守卫与结果

- 精确 R04 指纹；遍历活跃 Proc 树，单一交换脚本 `0x08A94D60`。命令要求 idle cursor `0x08A94D88`、callback `0x0809DDF9`、当前锁0／sleep0，以及实际父项菜单脚本 `0x08A946E8`、父锁1。不能把池中的旧记录当作活跃画面；非阻塞 UI children 合法存在，因此不以 child=0 代替锁与回调核验。
- 仅完整、压紧的两组5槽物品；单位指针、部署槽、人物／职业指针及状态必须一致。请求选中的空位必须是游戏可选择的第一个空位；两边相同原值的无效果交换被拒绝。
- `selectedItemSlot` 和 `helpBoxItemSlot` 均须为 `0xFF` 才能发起新命令；执行中按预期验证它们和光标。原始世界地图准备样本 chapter=2、phase=`0x40`、turn=0，无 MAPTASK；不要求普通玩家战场 phase 或 chapter 的准备位。
- R04 实际 Thumb 中，`CheckValidLinkArenaItemSwap`（`0x0809A178`）调用 `0x08042E1C`；后者读取 `BmSt+4 & 0x40`。当前命令拒绝该联机竞技场标志，不冒充已适配该模式。
- GameInput 提供同步的空输入 revision token，捕获两个采样间一按一松的实体／触摸输入。执行每帧检查输入、前后台与取消代次；重复提交由宿主 busy 及成功后上下文 revision 失效共同约束。
- 实际交换结果须与完整 u16 交换、两边空槽压紧后的预期完全一致才报告成功。随后保存当前分支的续玩状态，不覆盖手动恢复点；保存失败明确报告物品已交换而保存未完成。
- 中断停止后续按键，保留实际游戏的菜单选择和物品状态，不伪报已回滚。新增 `releaseKeys` JNI 在退出命令时释放合成按键，不通过额外推进游戏帧来释放；取消采用递增代次，避免排队开始时清除已到达的取消意图。

## 开发验证

初次 native 验证在 API35 x86_64 独立模拟器完成，`LocalPrepTradeTest` 四项通过：

1. 原游戏完整物品交换；同一旧请求再次提交在推进帧之前被拒绝。
2. 向空位转交、来源压紧；保存并重载后结果一致。
3. 原生 A 选中或 R 帮助状态拒绝新交换，拒绝时不推进帧。
4. 选中之后、实际交换之前中断，两边物品未变，原生选中状态仍保留。

测试使用缓存目录中的独立核心和 ROM／状态副本，未操作 UI 会话目录。每项结束重新核对输入 ROM 与状态文件摘要不变。源状态 `r04-wide-agent-worldmap-prep-trade.state` SHA-256 为 `97f697fd9b5f3423742d565449ad9a5de94be536dbd57e2c809bb73815b34efb`。

一次交换日志为 **17 帧、144.0795 ms**（`System.out`，API35 测试模拟器，含逐帧 RAM 捕获与守卫）。这是一笔操作的开发观测，不是 Thor 延迟或长期性能结论。执行器对每次请求设置160帧上限，无 sleep 或网络调用。

最终全工程 **68项 JVM 测试通过，0失败、0跳过**，启用四份本地 ROM 与 FE8／FE7 回放。应用及 instrumentation APK 的 arm64-v8a／x86_64 构建通过。新增能力声明后，原有“所有构建正常背包均不可用”的断言已更新为仅 R04 的限定准备交换可用；其他构建仍不继承该能力。

最终候选版在 API35 x86_64 共 **31项原生测试通过**：核心5、内存事务5、运行时6、准备交换5、FE8场景2、FE8研究恢复5、R06读取／恢复／跨引擎隔离3。准备交换第5项确认中断时可读取并释放原生按键 mask，第二次释放返回0，EWRAM／IWRAM不因释放而推进；另明确按住B时释放前 mask=2。日志保存在 `.local/inventory/final-build.log` 和 `final-native.log`。

## 实际界面验证

独立测试模拟器设置为2592×1240、369dpi，单屏右侧操作面板为1080×1240，与读取到的 Thor 下屏像素及密度一致。使用从真实原游戏流程取得的 R04 准备交换状态，另建 `Inventory validation` 分支，不操作用户 Thor 存档。

- 背包首页可直接看见物品、耐久、类别及拥有者；筛选、编号查找、准备交换按需展开。物品详情与两件不同物品的左右对比可用。
- 触摸输入名称编号 `02DD`，结果为1项，仍为原角色槽1／物品槽2，耐久25/30；未用筛选后的列表下标执行交换。
- 切换仓库显示当前0项、容量100格；未知仓库的界面分支显示“状态未知”，不当作空仓库。
- 在实际下拉菜单选中非首格，切到战场再返回背包后选择仍保留。下拉窗不抢实体按键焦点，UIAutomator单窗口树不含弹窗时使用实际截图定位与后续界面字段确认，未把查找失败当作通过。
- 实际确认两次不同槽位的交换，上屏原游戏物品栏与副屏同步；成功提示保留在背包首页。交换后旧物品对比引用失效，过滤／选槽不误指向新的物品。
- 浅色、深色与1.3倍字体检查通过，首页按钮及物品内容无横向溢出；详细列表共同纵向滚动。截图和界面树在 `.local/inventory/`。

这是开发模拟器证据，Thor 上的新背包与准备交换仍待用户反馈。
